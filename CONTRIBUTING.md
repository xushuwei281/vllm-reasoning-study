# Working on the study

The measured campaign is complete. Treat its saved observations, plans, trained
surrogate checkpoints and resource ledger as research evidence. Make new
experiments in fresh output directories with new run identifiers.

## Local development

Use Python 3.11 and an isolated environment:

```sh
python3.11 -m venv work/analysis-env
work/analysis-env/bin/python -m pip install -e '.[test,report,word]'
work/analysis-env/bin/python -m pytest -q
```

These tests use CPU models, fixtures and a local fake HTTP server. They do not
allocate a GPU or call a hosted inference service. Keep this environment separate
from the vLLM serving container.

Changes to scoring, optimization, data separation or accounting should include
tests of the relevant behavior. Describe the problem, the resulting behavior and
the validation performed in a pull request.

## Evidence and reports

The compact Git repository contains summaries and the report inputs. Full raw
responses and telemetry are available in the [evidence release](docs/github-release.md).
Use that separate snapshot to rerun the measured analysis.

The report text is generated by `scripts/build_continuation_report.py`. Its
completion checks require consistent measured evidence and terminal accounting.
The PDF renderer is `scripts/render_continuation_pdf.py`; the editable Word
renderer is `scripts/render_word_report.py`. Inspect the rendered pages after
changes to either format.

The original execution source hashes are recorded in
`results/continuation/search-plan.json`. A changed implementation is a new
version; it must not be represented as the code used for the archived campaign.
The existing raw results should never be edited to make a new analysis pass.

New live experiments need a separately authorized resource budget. The archived
eight-hour allowance and cloud job are historical records, not an active service.
