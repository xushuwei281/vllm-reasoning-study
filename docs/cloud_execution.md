## Runtime and reproduction

Run the project inside the pinned image using `python3`. The serving image supplies vLLM 0.10.2, PyTorch 2.8.0+cu128, Transformers 4.56.1 and huggingface-hub 0.34.4. The original local analysis environment remains separate; its package pins must not replace the image's serving dependencies. Install the project with `python3 -m pip install --no-deps -e .`, then the extra analysis dependencies in `requirements-cloud-analysis.txt`. The measured environment, NVIDIA driver, NCCL version and GPU memory are recorded in `results/continuation/environment.json`. Its 48 logical CPUs and approximately 200 GB host-visible RAM describe the host inventory, not the 12-vCPU/46-GB flavor entitlement. Its generic Apple unified-memory note is inapplicable to this CUDA job and is preserved as raw provenance.

`python3 scripts/hf_continuation.py setup` verifies the installed CLI and downloads the immutable model revision. The version-specific preflight uses ordinary `vllm serve --help` for 0.10.2: that release interprets `--help=all` as a substring search for “all.” The unsuccessful preflight artifact is retained. The source verification used the [pinned v0.10.2 argument parser](https://github.com/vllm-project/vllm/blob/v0.10.2/vllm/entrypoints/utils.py).

Development pilots are run with `python3 scripts/hf_continuation.py pilot <spec.json>`. After the measured default reference and immutable search plan exist, `python3 scripts/hf_continuation.py campaign` interleaves the three methods. Each method has independent observations and checkpoints; no measured performance table is provided for free. Arrival schedules differ between trial indices and match across methods at the same index. The question cohort and generation seeds remain fixed. This supports configuration generalization conditional on one workload, not unseen-content generalization from the internal neural split.

`python3 scripts/hf_validation.py validate` selects and independently remeasures the finalist on 150 reserved training questions. The execution criterion is the original empirical 2-point accuracy constraint plus the error limit. Paired bootstrap intervals and the exact harmful-discordance bound are retained separately; statistical noninferiority is claimed only if its bound passes. The cohort size cannot be extended after seeing outcomes. A failed empirical gate does not authorize candidate substitution or test access.

Only a successful immutable freeze permits `python3 scripts/hf_validation.py final`. The four arms use the frozen default/tuned configurations and two output allowances, matched question seeds and whole-device reservation slots. Startup reduces available service time; teardown and allocated idle padding are charged. All actual overshoot remains in the ledger. Test IDs are selected by the declared seed before their content is read.

The original GPU-hour allowance is not reset by moving environments. Metal pilots are diagnostic evidence and never enter the cloud surrogate's training data or live optimizer curves. No W8A8, multi-GPU tensor parallelism, disaggregation or Ascend HCCL result is implied by this CUDA continuation.
